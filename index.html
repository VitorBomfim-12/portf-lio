01 // PROBLEMA RESOLVIDO

A operação enfrentava uma gestão de demandas fragmentada e descentralizada: diferentes times utilizavam ferramentas isoladas e processos burocráticos desconectados entre si. Essa fragmentação provocava ruídos de comunicação intersetoriais, perda de rastreabilidade no andamento dos serviços em campo e falta de visibilidade em tempo real sobre prioridades e prazos de SLA para a liderança.

02 // SOLUÇÃO DESENVOLVIDA

Aplicação web full stack construída com Next.js e TypeScript que unifica todo o ciclo de vida das ordens de serviço: cadastro de projetos e abertura de tickets vinculados, indicadores visuais de SLA com ordenação automática por prioridade, registro de logs técnicos de atendimento, controle de contas e perfis (Analista Comercial, Gestor, Técnico, Suporte Interno/Externo), fluxo de aprovação de encerramento e alertas automáticos por e-mail.

03 // CONTRIBUIÇÕES PESSOAIS (PRODUCT OWNER & DESENVOLVEDOR)

  • Product Ownership & Engenharia de Requisitos: Atuação como Product Owner da equipe FawkesCode — elaboração e priorização do Product Backlog (24 User Stories distribuídas em 3 Sprints), definição dos critérios de Definition of Ready (DoR) e Definition of Done (DoD) e alinhamento com stakeholders.
  • Mensageria & Notificações (Back-end): Implementação da feature de envio de e-mails para gestores de equipe ao associar tickets, estruturando uma classe dedicada para encapsular o Nodemailer e incluir automaticamente o contexto do projeto no corpo da mensagem.
  • Otimização Arquitetural & API: Criação de rotas REST no App Router do Next.js e refatoração estrutural da página de tickets para reduzir a quantidade de requisições redundantes ao servidor.
  • Dados, Testes & Governança de Código: Desenvolvimento de scripts SQL de seed para popular o banco de dados via SGBD, script de teste de rotas da API e documentação da estratégia de branches e padrão de commits da equipe.

We Logic — Gestão de Processos de Compras

Empresa Parceira: Newe Log (identificação textual sem logotipo)

REPOSITÓRIO GITHUB ↗

01 // PROBLEMA RESOLVIDO

O ciclo de compras corporativas era conduzido de forma manual e descentralizada, gerando pedidos sem rastreabilidade, aprovações sem registro formal e ausência de visibilidade em tempo real dos níveis de estoque. Esse cenário favorecia compras não autorizadas, retrabalho entre setores e dificuldade para auditorias financeiras e operacionais.

02 // SOLUÇÃO DESENVOLVIDA

O We Logic é uma aplicação desktop desenvolvida em Java com JavaFX e MySQL voltada à governança completa das aquisições: abertura de pedidos com numeração automática, fluxo formal de aprovação com parecer registrado, controle de estoque com alertas de nível mínimo, módulo de cotações comparativas entre fornecedores, registro de recebimento com nota fiscal e dashboard gerencial.

03 // CONTRIBUIÇÕES PESSOAIS (DESENVOLVEDOR BACK-END & DADOS)

  • Modelagem & Integridade de Banco de Dados: Criação, refatoração e prototipagem das tabelas e queries SQL no MySQL, eliminando redundâncias, corrigindo dependências de criação e implementando regras de integridade referencial (exclusão em cascata).
  • Camada de Persistência & Conexão: Implementação da classe de conexão com o banco de dados em Java, garantindo desacoplamento e segurança das credenciais.
  • Configuração & Boas Práticas de Ambiente: Estruturação inicial com Spring Boot (via Spring Initializer), adição de dependência no pom.xml para leitura de variáveis de ambiente (.env) e proteção de dados sensíveis no .gitignore.

Projeto Caronte — Agente de IA para KYC & Prevenção a Fraudes

Repositório: VitorBomfim-12/langchain_project

VER CÓDIGO NO GITHUB ↗

// DESAFIO & CONTEXTO

Empresas de meios de pagamento (maquininhas POS) precisam auditar rapidamente o perfil de estabelecimentos e proprietários antes de aprovar crédito ou antecipação de recebíveis. Analisar manualmente padrões de chargeback, pulverização de CNPJs/lojas sob um mesmo CPF, ataques de velocidade (velocity attacks) e incoerências geográficas em transações é lento e propenso a falhas.

// ARQUITETURA DA SOLUÇÃO

Desenvolvi uma API REST em FastAPI organizada em camadas (routes, schemas/DTOs, services, models e agents) que orquestra o agente de IA Caronte usando LangChain / LangGraph e Google Gemini 2.5 Flash. O agente é obrigado por engenharia de prompt a invocar Tools SQL reais para auditar transações e métricas antes de emitir um parecer estruturado (validado com Pydantic) contendo o nível de risco (RiskEnum) e justificativa baseada em evidências.
